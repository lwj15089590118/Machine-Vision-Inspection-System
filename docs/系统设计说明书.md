# 系统设计说明书 —— 工件视觉定位与缺陷检测系统（仿真版）

> **仿真声明**：本项目无真实相机与 PLC。工件图像由 `simulator/synth.py`
> 程序合成（模拟工业相机俯拍），PLC 由 pymodbus Modbus/TCP 从站软件模拟。
> 文中全部性能指标均为**仿真验证值**，只证明算法链路与工程结构的正确性，
> 不等价于真实产线性能；迁移到真实设备需重新选型、标定与验收。

---

## 1. 项目概述

### 1.1 目标

对传送带上的圆形法兰盘工件完成：

1. **定位**——输出工件中心 (x,y)、旋转角 θ、缩放 s（像素级 + 毫米级）；
2. **检测**——识别划痕 / 崩边 / 污渍 / 螺栓孔偏移 / 螺栓孔缺失五类缺陷，
   按 NG 判定规则表输出 OK/NG 结论与结构化结果 JSON；
3. **联调**——通过 Modbus/TCP 寄存器与上位机（PLC）握手：触发、回写
   结果码 / 缺陷位 / 定位偏差定点数、心跳、看门狗；
4. **可视化**——Flask + ECharts 看板实时展示标注帧、良率、节拍与记录。

### 1.2 仿真对象定义

| 项目 | 设定 |
|---|---|
| 视场 | 800×600 px ↔ 80×60 mm，即 **像素当量 0.1 mm/px** |
| 工件 | 圆形法兰盘：外圆 R=100px(10mm)、中心孔 R=30px、4×螺栓孔 R=10px @分度圆 64px、键槽 26×16px |
| 位姿随机 | 中心 ±100px、旋转 ±30°、缩放 0.9~1.1、亮度 ±20%、高斯噪声 σ=4 |
| 成像条件 | 固定光照不均匀场（逐帧不变）、皮带纹理逐帧变化 |

键槽是刻意设计的**旋转对称性破坏特征**：圆盘+4 孔布局本身具有 90° 旋转
对称性，没有键槽就无法唯一解算角度（见 §4.3）。

要点：

- **工件事实单源（ADR-0001）**：locate 与 inspect 的几何期望值与黄金
  资产（匹配模板、基准比对图）一律取自 `part_model`，生产算法不 import
  仿真器；`make_reference()` 以固定种子生成，保证基准与测试帧表面纹理
  严格一致——这是"基准比对法"可行的前提，该前提现由 part_model 承载；
- **合成器是测试期的"相机"**：simulator 组合 part_model 的名义图层，
  叠加缺陷注入与位姿/亮度随机化后供 run_batch 与 plc_server 使用；
- **看板与视觉服务完全解耦**：通过三条落盘文件（记录流 JSONL、最新标注
  PNG、最新结果 JSON）做文件总线，看板挂掉不影响产线检测；
- **手动触发走真协议**：看板按钮以 Modbus 客户端身份写 HR0=1，与真实
  上位机同一通路，而非绕过协议直接调函数。

## 4. 关键设计与算法选型理由

### 4.1 相机标定（calib/）

**方法**：张正友平面标定（cv2.calibrateCamera）。

**为什么做"正向仿真验证"**：真实场景中标定精度无法即时验证；本项目反向
构造真相——先以已知内参 K、畸变系数 (k1,k2,p1,p2,k3) 把理想棋盘格渲染成
带畸变图像（数值迭代求逆映射再 remap，物理过程一致），角点真值由解析投影
直接得到；再走标准逆向流程标定，**用"标定值 vs 注入真值"的偏差来证明
标定流程本身正确**。

**验收门槛**：重投影误差 RMS ≤ 0.5px。实测 **0.0919px**（20 张、seed=3，
仿真验证值）；实测像素当量 0.10001 mm/px（设定 0.1，偏差 1e-5）。角点
亚像素细化后检测误差均值 0.54px，说明残差主要来自角点提取而非模型。

**工程接口**：`load_calibration() / undistort_image() / px_to_mm() /
mm_to_px()`；主合成链路按"已校正成像"仿真（无畸变），故 locate/inspect
无需去畸变预处理，标定模块的价值在方法论演示与像素当量复检。

### 4.2 图像合成器（simulator/）

成像链路仿真（与真实相机逐环节对应）：

```
皮带背景(随机纹理) ⊕ 法兰盘图层(基准位姿绘制)
    →仿射变换(平移/旋转/缩放)→ 图层合成
    → ×固定光照不均匀场 → ×整帧亮度增益(±20%) → +高斯噪声(σ=4) → 8bit
```

三个关键设计：

1. **缺陷画在基准坐标系的盘面图层上**，随图层一起做仿射变换 → 真值坐标 =
   仿射(缺陷基准坐标)，像素级无误差，批量验收的对照因此绝对可靠；
2. **表面拉丝噪声固定种子**：基准图与每张测试图的纹理逐像素相同，
   基准比对的残差只剩传感器噪声与位姿矫正误差，不引入虚假差异；
3. **光照场逐帧不变**：模拟"相机与光源刚性固定"的真实工况——正因如此，
   增益归一化（§4.4）才能把 ±20% 亮度增益干净地消掉。

### 4.3 定位（locate/）：三级"粗→精"流水线

| 级 | 方法 | 输出 | 为什么这么做 |
|---|---|---|---|
| ① 粗定位 | cv2.matchTemplate(TM_CCOEFF_NORMED)+基准模板 | 中心 ±数px | 圆盘特征对 ±30°旋转和 ±10%缩放不敏感，归一化相关分数仍给出可靠峰位；速度 O(N) 可控 |
| ② 中心/缩放精修 | ROI 内 Otsu 二值化 → 最大连通域 → **凸包填充** → 质心 + 最小外接矩形等效半径 | 亚像素中心；s = r/R_base | 凸包把孔/键槽/崩边等凹缺补回完整材料圆盘，质心不被缺陷拉偏；半径自校准（基准图同尺子测量）消除"亮盘面≠外缘"的系统偏差 |
| ③ 角度解算 | a) 旋转归一化互相关粗解(±46°/2°步进)；b) **键槽角向灰度剖面精修** | θ（0.1°级） | 圆形工件最小外接矩形角度无意义，必须靠破坏对称的特征；剖面法用"同行皮带参考像素"做光度归一，把皮带行条带亮度严格抵消 |

**角度精修原理**：外圆暗环灰度≈80×增益，键槽挖空处露出皮带≈110×增益。
在预测方位 ±22° 窗口沿 [0.965,0.995]·R 径向带做角向剖面（0.5°/bin），
Otsu 分离两总体后加权质心即键槽方位。窗口设计依据：键槽角向半宽约 8°
（atan(13px/92px)），±22° 保证两侧各留 ~14° 正常环段供 Otsu 分总体。

**为什么不用深度学习**（高频面试题）：
- 训练依赖大量标注与样本多样性，而本任务可用**解析真值**与**几何先验**
  （已知外径、孔位、键槽尺寸）精确建模，传统几何方法即可达到亚像素精度
  （实测中心 P95=0.033mm，仿真验证值）；
- 工业现场要求**可解释、可回归验证**：模板分数、Otsu 阈值、剖面质心每个
  数值都能定位失败原因；网络输出黑盒难以过 FMEA；
- 无 GPU 的工控机部署约束下，73.8ms/件的 CPU 节拍（仿真验证值）更现实。
  若缺陷种类扩展到"无法规则化描述"的形态学范畴（如复杂纹理异常），才是
  引入学习方法的合适时机（见 §9）。

### 4.4 缺陷检测（inspect/）：三个互补分支

单一方法覆盖不了五类缺陷，按缺陷的物理本质分治：

| 分支 | 目标缺陷 | 原理 | 关键抗干扰 |
|---|---|---|---|
| A 基准比对 | 划痕/污渍（面域） | 仿射矫正回基准位姿 → 增益归一化 → absdiff → 自适应阈值 → 形态学 → 连通域聚类 | ①环形区中位数比值消 ±20% 增益；②阈值用 中位数+3×MAD 而非均值+kσ——缺陷自身会抬高均值造成"自污染"，把弱缺陷压到阈下；③双边模糊抑制 0.3~0.7px 矫正残差在锐边的细环假差 |
| B 外圆轮廓 | 崩边 | 材料边界 360° 角向半径剖面对照基准，局部内凹 >6px 且连续弧长 ≥2° | 键槽扇区 ±12° 保护角（键槽天然"内凹"，必须排除）；崩边规划时避开键槽 ≥25° 双保险 |
| C 几何测量 | 孔偏移/孔缺失 | 霍夫圆粗检（环带内搜索）→ **径向剖面亚像素精修** → 与公差比较 | 匹配窗 18px 兜住最大偏移 15px；降阈值重试一次抗漏检；"填实佐证"区分真缺失与霍夫漏检 |

**分支 C 的亚像素精修（本项目的关键教训）**：霍夫累加器只给整像素级
半径（±1~2px 抖动），而孔径公差 ±0.3mm = 直径 3px——量化噪声直接顶穿
公差，500 帧验收中贡献了全部 13 例误报。修复：以霍夫圆为初值，36 条射线
找"孔内暗→盘面亮"灰度 50% 交叉点并线性内插到亚像素，Kasa 最小二乘圆
拟合输出精确圆心与半径（有效点 <12 时退回霍夫粗值保鲁棒）。修复后误报
13 → 0。

**孔事件与面域分支的管辖权划分**：
- 未判缺失/偏移的孔：在比对掩膜上抠掉"半径+3px"保护圈——亚像素矫正
  残差会在高对比孔缘产生细长月牙差分（OK 件误报主源之一），源头抑制；
  不能按"碎片质心距孔心 <R 就剔除"实现：实测会把恰好压在孔附近的
  807px² 真实污渍整团吃掉（按像素掩膜只损失重叠部分）；
- 已判异常的孔：保留其特征 blob，供"填实佐证"（filled_confirmed）与
  分类守卫使用，防止回填 blob 与路过划痕聚类合并后被整体跳过。

**blob 分类规则**：长宽比≥3 且等效宽度≤8px → 划痕；外缘带(r>R−18px)
大块 → 崩边兜底；其余 → 污渍。（8px 依据：划痕标注宽 2~3px 经阈值膨胀+
闭运算+折线弯曲后实测 ≤7.1px，污渍团块 ≥15px，中间留足隔离带。）

### 4.5 NG 判定规则表

| # | 条件 | 阈值 | 说明 |
|---|---|---|---|
| 1 | 任一面域缺陷面积 > 30px² | 0.3 mm² | 小于它按工艺目检口径不算缺陷 |
| 2 | 外圆局部内凹 > 6px 且弧长 ≥2° | 0.6mm | 崩边 |
| 3 | 螺栓孔位偏移 > ±0.5mm | 精修后测量 | 孔偏移 |
| 4 | 螺栓孔径偏差 > ±0.3mm | 直径 3px | 测量报告项（见 §6.2 注） |
| 5 | 螺栓孔缺失 | — | 安全侧失效模式 |
| 6 | 定位失败 | 模板分 <0.30 | 看不见工件按 NG 处理（安全策略） |

置信度 = 0.35×模板分 + 0.35×角度相关峰 + 0.30×孔检出率，低于 0.75 标记
"低置信"提示人工复核。

### 4.6 PLC 链路（plc_link/）

**寄存器规划**（保持寄存器 HR，zero_mode 地址从 0 起）：

| 寄存器 | 含义 | 编码 |
|---|---|---|
| HR0 | 触发命令 | 上位机写 1=正常触发；2=触发并模拟卡死（看门狗测试入口）；处理后自动清零 |
| HR1 | 忙闲状态 | 0=空闲 1=忙 2=完成（本次结果有效） |
| HR2 | 结果码 | 0=无 1=OK 2=NG 999=看门狗故障 |
| HR3 | 缺陷类型位组合 | bit0划痕 bit1崩边 bit2污渍 bit3孔偏移 bit4孔缺失 bit5定位失败 |
| HR4/5 | X/Y 定位偏差 | int16，0.01mm 定点（两补码，config.to_int16/from_int16） |
| HR6 | 工件角度 | int16，0.1° 定点 |
| HR10 | 心跳计数 | uint16 自然回绕；每完成一轮 +1，空闲期按 1s 周期 +1 |

**服务状态机**：IDLE（轮询 HR0 + 空闲心跳）⇄ BUSY（工作线程处理 + 看门狗
监测）。工作线程异常不得杀死主循环；看门狗超时写 999 并置 DONE，迟到的
真实结果凭 `_faulted` 标志作废，故障恢复后自动回到正常流程。

**踩坑实录（pymodbus 3.x 异步架构）**：初版调用
`StartTcpServer()`——它在 pymodbus 3.6 里是 `asyncio.run(StartAsyncTcpServer(...))`
的便利包装，**阻塞调用线程直到 shutdown**，导致主循环永远启动不了；
症状极具迷惑性：Modbus 端口能连、寄存器能读写，就是触发无人消费、心跳
不动。修复：专用守护线程内 `asyncio.new_event_loop()` → 构造
`ModbusTcpServer`（构造器要求 running loop）→ `run_until_complete(serve_forever())`；
停止时 `run_coroutine_threadsafe(server.shutdown(), loop)`。

**客户端同步协议（两段式等待）**：上一轮完成后 HR1 会一直停在 DONE，
客户端写完触发若直接轮 DONE，会把旧状态当本轮结果（读到的是上一帧的
答案）。必须先等"受理"（HR1=BUSY_BUSY）再等"完成"——这是工业握手的
通用做法，也是本项目自测脚本第一版踩过的坑。

### 4.7 看板（dashboard/）

- 只读消费文件总线（records.jsonl / latest.png / latest.json），坏行容忍、
  半行容忍，轮询永不抛错；
- 统计口径：良率 = OK/(OK+NG)，FAULT 不进分母；NG 类型分布按条目逐类型
  计数；节拍曲线取最近 120 件；
- ECharts 走 CDN，主源失败自动切备用源（onerror 回退）；
- 标注图按 mtime 变化才刷新 src，避免闪烁。

## 5. 公差与阈值设定依据（config.py 全表精选）

| 参数 | 值 | 设定依据 |
|---|---|---|
| MM_PER_PIXEL | 0.1 | 视场 80mm/800px；标定实测 0.10001 复核 |
| TM_SCORE_MIN | 0.30 | 正常帧模板分 >0.9（仿真验证值），取 1/3 作失败判据，兼顾遮挡/强噪 |
| DIFF_ABS_FLOOR | 20 灰度级 | 干净件残差实测余量 >10 级（噪声 σ=4 → 差分 σ_d≈5.6），下限取 ~3.5σ_d 防误报 |
| DIFF_ADAPT_K | 3.0（中位数+3×MAD） | MAD×1.4826≈σ 的稳健估计；3σ 对应单点误检率 ~0.27%，配合面积过滤足够 |
| MIN_BLOB_AREA_PX | 12 | 形态学开运算后孤立噪点典型面积 <8 |
| CLASS_SCRATCH_ASPECT / W_MAX_PX | 3.0 / 8px | 见 §4.4 分类规则依据（批量调参实测划痕 w_est≤7.1、污渍≥15） |
| DEFECT_AREA_NG_PX | 30px² = 0.3mm² | 与工艺目检口径一致的演示阈值 |
| RIM_DEVIATION_NG_PX | 6px = 0.6mm | 崩边注入半径 14~22px，判定线取其 1/3 强，保证显著缺陷必报 |
| HOLE_POS_TOL_MM | ±0.5 | 注入偏移 0.8~1.5mm 必然超差；正常孔精修后 P95 偏差 0.03mm 级，余量充足 |
| HOLE_DIA_TOL_MM | ±0.3 | 直径 3px；**必须配亚像素精测**（§4.4），否则霍夫量化噪声即超差 |
| HOUGH_MIN/MAX_R | 7/14px | 名义半径 10px，覆盖缩放 0.9~1.1 矫正残余 ±1px 再放宽 |
| WATCHDOG_TIMEOUT_S | 2.0 | 正常处理 ~0.15s，取 13 倍余量；给上位机明确的故障语义 |
| KEYWAY_AREA_MIN/MAX_PX | 250/620 | 键槽连通域名义面积 ≈26×16=416px²，±50% 包络区分崩边缺口 |

## 8. 调参记录与踩坑（工程复盘）

以下每条都有批量数据支撑（详见 git 式演进过程中的 run_batch 输出）：

1. **霍夫量化噪声顶穿孔径公差**（500 帧 13 例误报的全部来源）→ 射线剖面
   亚像素圆拟合，误报 13→0，代价 +20ms/件；
2. **孔缘月牙差分**（亚像素矫正残差在高对比边缘的必然产物）→ 未判异常孔
   的"半径+3px"掩膜保护圈；期间试过"碎片质心剔除"方案（20px/13px 半径），
   分别把跨孔真实污渍整团误吞，最终改为像素级掩膜——按影响范围最小原则
   选型；
3. **划痕宽度分类阈值 6px 过紧**（漏判划痕 w_est 落在 6.3~7.1）→ 放宽至
   8px 并参数化进 config，依据是划痕/污渍两类实测分布间有 2 倍隔离带；
4. **合成器真值 bug**：bolt_missing 先选孔时 bolt_shift 可与之落在同一孔，
   "回填+新孔"的图像效果等价纯偏移但真值记两个缺陷 → 修正避让逻辑对称
   生效（used_holes 集合），否则验收对照失真；
5. **角度两级细化尝试失败**：第二级 ±6° 窗口完全落入键槽亮段内部（键槽
   角向半宽约 8°），Otsu 退化为单总体导致质心失锁，P95 从 0.72° 恶化到
   2.84° 且连带基准比对误报——回退；再试"单窗加密+双线性插值"P95 持平
   （0.75°），证明瓶颈在边缘模糊不在采样量化，遂保留原实现并把门槛定为
   0.8°（对应分度圆切向 0.08mm，为孔位公差 1/6，不影响判定）。
   **负结果也记录**，这是调参纪律；
6. **pymodbus StartTcpServer 阻塞**（§4.6）：端口通、寄存器活、业务死的
   "三不像"症状；以及 **客户端旧 DONE 状态竞态**：都必须等状态迁移而非
   等状态值；
7. **Windows 端口重复绑定陷阱**：本机 5000 被另一开发服务长期占用，
   Flask 二次绑定成功但请求进了先绑定者——表现为"打开看板却是别的页面"；
   看板默认改 5001。同理排查过 502 端口上的僵尸 plc_server。

## 9. 已知局限与改进方向

| 局限 | 影响 | 可能的改进 |
|---|---|---|
| 中心孔邻域为比对盲区（r<33px 保护圈） | 极小污渍落入该区可能漏检（件级 500/500 未发生） | 多光源成像或 3D 测量补充 |
| 类型误判存在（划痕↔污渍混淆 ~13~21%） | 影响根因分析不影响拦截 | 分类特征加周长复杂度/灰度剖面；或轻量 CNN 分类器只做"已检出 blob 的命名" |
| 单帧离线检测 | 无法评估运动模糊 | 加速运动仿真 + 曝光时间建模 |
| records.jsonl 全量读取 | 数万条后轮询变慢 | 字节偏移增量读 / SQLite |
| Flask 开发服务器 | 并发能力弱 | gunicorn/waitress + Nginx |
| 全部指标为仿真验证值 | 不代表真实产线 | 真实相机选型→光源打样→GT&W 试运行重标定 |
