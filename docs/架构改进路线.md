## 一、重构方法学（本轮跑通的闭环，后续照此执行）

### 1. 增量纪律

- **一处一提交**：每个逻辑单元一个 commit；交付时给 Summary/Description；
  上一处未合入不开工下一处。
- **基线先行**：动第一行代码之前，先固定参数跑全量留黄金样本：
  ```powershell
  python run_batch.py --count 100 --seed 42          # 快验口径
  cp data/batch_report.json "$env:TEMP\baseline_batch_report.json"
  ```
- **双重验证**：每步先快验（100 帧）再收官（500 帧）；行为级改动补
  负向检查（如"旧 import 必须 ImportError"）。
- **收官对账**：最后一步用 `--count 500 --seed 42` 与项目原始交付数字
  逐项核对（README §性能指标 / 设计说明书 §7），证明全程数值等价。
- **文档随增量同步**：架构图、接口口径、目录结构在改动落地的同一提交
  内更新，不留漂移窗口。

### 2. 回归工具

```powershell
python tools/metrics_diff.py <baseline.json> <current.json>
# 自动剔除 takt_ms 与 gates[].actual（墙钟噪声），其余逐键深比较；
# 一致输出 METRICS-IDENTICAL(exit 0)，差异逐条列路径(exit 1)。
```

### 3. 已验证的经验教训

| 教训 | 说明 |
|---|---|
| 对比必须排除墙钟 | `takt_ms` 与含节拍字符串的门槛实测值天然逐次不同，纳入对比必假报 |
| JSON 对比用 Python | PowerShell 5.1 `ConvertFrom-Json` 解析中文 UTF-8 会静默失败 → "空比空"假一致（本轮真实踩坑） |
| rng 流等价技巧 | 平移采样区间边界（如 `uniform(kw+25, kw+335)`）不改变随机数消耗形状 ⇒ 同 seed 输出逐位不变 |
| 搬迁不改执行序 | 纯函数原样搬运 + 调用方结构不变 = 像素级等价；缺陷绘制外移循环即此法 |
| 行为级负向测试 | 解耦类改动要验证"旧路径已死"（`from simulator.synth import make_reference` 应 ImportError） |
| 断言前先核实语义 | 材料掩膜不含孔挖空（孔=盘内特征只挖灰度层）——先打印事实再写断言，测试挂了先分清"产品错还是断言错" |
| 隐式约定要挖到底 | 键槽方位角名义上三处散写，实际五处（locate 两处换算漏网）——单源化前 grep 全部消费点 |
