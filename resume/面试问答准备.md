# 面试官最可能深挖的 10 个问题及回答要点

> 每题先给"一句话结论"，再给展开要点。所有数字注明（仿真验证值）。
> 回答时主动引用调参记录/负结果，展示工程纪律。

---

### 1. 为什么用模板匹配而不用深度学习？

**结论：任务有解析真值和几何先验，传统几何法已达到精度极限，且可解释、
可回归验证、CPU 实时。**
- 本项目能拿到像素级真值与已知几何（外径/孔位/键槽），模板匹配+凸包质心+
  键槽剖面实测中心 P95=0.033mm、角度 P95=0.47°（仿真验证值），远高于检测
  公差需求；
- 工业验收要求每个失败案例可归因（模板分低？Otsu 失败？剖面无对比度？），
  黑盒网络难做 FMEA 与根因分析；
- 无 GPU 工控机约束，103ms/件的 CPU 节拍现实；数据量小（合成 500 帧）训
  络反而易过拟合；
- 加分回答：如果缺陷形态无法规则化描述（随机纹理异常），会在"已检出
  blob 的分类命名"环节引入轻量 CNN，定位仍用几何法——按环节选型而非
  全盘二选一。

### 2. 重投影误差是什么意思？0.5px 门槛怎么定的？

- 定义：把三维标定板角点用"估计出的内外参"重新投影回图像，与实际检测到
  的角点坐标的残差 RMS。它衡量"整套相机模型对观测的解释程度"；
- 我的仿真里还能对照注入的真值参数（fx/fy/畸变系数逐项比对），证明流程
  正确而不只是拟合了噪声；实测 RMS=0.092px，角点检测本身误差 0.54px，
  说明残差主要来自亚像素提取；
- 0.5px 是行业常用工程门槛（约为像素当量 0.1mm 的二十分之一），本项目
  用它做自动化 PASS/FAIL 判据。

### 3. 光照变化（±20% 亮度增益）是怎么抗干扰的？

三层防线：
1. 合成器把光照场设计为**逐帧不变**（灯罩固定），只有整帧增益随机——
   增益是乘性的，基准比对前用"环形区中位数比值"归一化即可消除；
2. 差异阈值不用均值+kσ 而用**中位数+3×MAD**：MAD 对离群不敏感，缺陷自身
   不会抬高阈值造成"自污染"；再叠加绝对下限 20 灰度级（≈3.5σ_d）兜底；
3. 定位的键槽剖面用**同行皮带参考像素**做比值，行条带亮度在分子分母间
   相消。若真实产线光照会缓变，再加光源闭环或定期自动重采基准图。

### 4. 误报率高了怎么调？（排查思路题）

按"误报来源分层定位"回答，并引用实战：
1. 先看 run_batch 错检明细 + batch_fp_*.png 标注图，归类 FP 的物理形态；
2. 我遇到的两大来源：①霍夫整数量化半径顶穿孔径公差 → 射线剖面亚像素圆
   拟合（13 例→0）；②矫正残差在高对比孔缘的月牙差分 → 未判异常孔抠
   "半径+3px"掩膜保护圈（强调：试过按碎片质心剔除会把跨孔真实污渍整团
   误吞，最终选影响范围最小的像素级方案）;
3. 阈值类调整必须看两类分布（干净件残差 vs 缺陷信号）之间有没有隔离带，
   不能拍脑袋；每次只动一个变量并用固定 seed 批量回归。

### 5. 角度是怎么测出来的？圆形工件不是旋转对称的吗？

- 圆盘+4 孔布局有 90° 旋转对称性，最小外接矩形角度无意义——所以我在
  合成器里设计了键槽特征破坏对称性；
- 三步：粗角度用"旋转到候选角与基准图做掩膜 NCC 取峰"；精角度用键槽处
  "暗环被打断露出皮带"的亮度对比，沿径向带做 0.5°/bin 角向剖面，Otsu
  分离后加权质心；窗口 ±22° 的依据是键槽角向半宽约 8°，两侧留足正常段
  供 Otsu 分总体；
- 主动讲负结果：试过第二级 ±6° 细化窗，因完全落入键槽亮段导致失锁，
  P95 从 0.72° 恶化到 2.84°，回退；单窗加密+双线性插值也无收益——说明
  瓶颈在边缘模糊不在量化，最终门槛定 0.8°（切向仅 0.08mm，公差的 1/6）。

### 6. Modbus 协议细节：寄存器怎么规划？定点数怎么处理？

- HR0~HR10 表格化讲解（触发/状态机/结果码/缺陷位/XY 偏差/角度/心跳）；
- 有符号量用 int16 两补码定点：X/Y 以 0.01mm、角度以 0.1° 为 LSB，写入
  前 `&0xFFFF`、读取后按 ≥0x8000 还原负数（config.to_int16/from_int16）；
- 状态同步协议：客户端写触发后必须**先等 HR1=1 受理、再等 HR1=2 完成**——
  上一轮 DONE 会保持到下一轮被消费，直接轮 DONE 读到的是旧帧结果（我自测
  脚本第一版就栽在这里）；
- 心跳双路径：空闲期周期 +1、每完成一轮 +1，上位机两种场景都能判活。

### 7. 看门狗机制怎么设计的？迟到结果怎么处理？

- 主循环 IDLE⇄BUSY 两态；触发受理时记 deadline=now+2s；BUSY 态每 5ms
  检查，超时即写 HR2=999+置 DONE 并打故障记录；
- 迟到的真实结果凭 `_faulted` 标志作废，不覆盖故障码——保证上位机看到
  的语义一致；
- 测试入口：写 HR0=2 让工作线程睡过时限模拟卡死（正常处理 0.15s 永不会
  自然超时，必须可注入才可验证）；实测 2.1s 动作、故障后下一次触发正常；
- 设计原则：工作线程任何异常不得杀死主循环（try/except 包裹 + 兜底写
  故障码）。

### 8. 基准比对法的原理？为什么崩边和孔不用它？

- 原理链路：按定位结果仿射矫正回基准位姿 → 增益归一化 → absdiff →
  自适应阈值 → 形态学 → 连通域聚类分类；
- 适用前提：位姿矫正误差 << 缺陷尺度。孔缘/外圆是高对比锐边，0.3~0.7px
  的亚像素矫正残差就会产生细环/月牙假差，信噪比天然差；
- 所以崩边改用"材料边界角向半径剖面对照"（几何量对位姿误差一阶不敏感，
  且有键槽保护扇区）；孔改用几何测量分支（霍夫粗检+射线剖面亚像素精修）；
  三个分支按物理本质互补，交叉验证（如缺失孔需比对分支"填实佐证"确认）。

### 9. 霍夫圆检测的参数怎么定的？为什么还要二次精修？

- 参数：minDist=15（孔间距 90px 的一半以下防漏）、半径窗 7~14px（名义
  10px×缩放余量）、param2=20 起步失败则降 6 重试一次抗漏检；
- 二次精修的原因是本项目的关键教训：霍夫累加器给整像素级半径，±1~2px
  抖动直接顶穿 ±0.3mm 孔径公差（直径 3px），500 帧里 13 例误报全部来自
  这里；修复用 36 条射线找灰度 50% 交叉点线性内插 + Kasa 圆拟合，实测
  干净件孔径偏差压到 <0.05mm 级，误报清零，代价约 +20ms/件；
- 鲁棒性：有效交叉点 <12 个（污渍压孔等）自动退回霍夫粗值，宁可测量粗
  也不崩溃。

### 10. 这个仿真项目和真实产线的差距在哪？怎么迁移？

诚实分层回答：
- 图像域：真实相机有感光噪声模型、镜头畸变、运动模糊、频闪——我的标定
  模块已有畸变处理能力，主链路加 undistort 预处理即可；运动模糊需补曝光
  时间建模；
- 数据域：真实基准图不能靠程序生成，要用标准样件实拍 + 定期自动重采；
  真值要靠人工复检抽验建立；
- 通信域：pymodbus 从站换真实 PLC 只需对方映射同一张寄存器表（协议文档
  已给全），两段式握手/看门狗/心跳语义不变；
- 验收域：所有指标标注了仿真验证值，迁移后须以真实 GT&W 试运行数据重新
  跑 run_batch 口径验收——这套验收框架（混淆矩阵/类型检出率/P95 误差/
  节拍/退出码）本身就是交付物之一。
